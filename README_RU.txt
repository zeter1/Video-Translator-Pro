разбит на пакет videotranslator/. Корневой video_translator.py остался совместимым

Hybrid AI v9 Pass 9 — качество перевода и финального видео
=======================================================

- `translation_glossary.json` теперь помогает не только после перевода: его source-термины
  передаются Whisper как bounded vocabulary prompt и сохраняются на всех окнах длинной записи.
  Шаблон: `translation_glossary.example.json`; подробности: `docs/TRANSLATION_GLOSSARY.md`.
- Если переводчик оставил термин из glossary без перевода, программа исправляет только этот
  термин и только когда он действительно присутствовал в исходном сегменте.
- Рядом с готовым MP4 автоматически сохраняются `_source_<lang>.srt` и
  `_translated_<lang>.srt`; Pause Sync учитывается в их таймкодах.
- При включённом оригинальном фоне программа использует FFmpeg sidechain compression:
  оригинальная речь автоматически приглушается во время русского голоса и возвращается между
  репликами. Если фильтр недоступен, остаётся старое совместимое смешивание.
- Pause Sync исправлен для современных FFmpeg, где duration-based `tpad` после trim/setpts
  мог потерять clone-кадры. Проверка использует реальные синтетические MP4, а не только mock.
- Явно оборванный видеопоток теперь блокирует публикацию результата вместо создания
  формально успешного MP4 с длинным участком без нормальных кадров.

Видео Переводчик PRO — Pause Sync Quality
=========================================

Состав архива:
- video_translator.py               — программа
- requirements.txt                  — Python-зависимости
- Запустить.bat                     — запуск на Windows
- Установить_зависимости.bat        — установка Python-библиотек на Windows
- CHANGELOG_RU.txt                  — список изменений
- Точность перевода.txt             — заметки по качеству перевода/озвучки
- build_exe.bat                     — сборка Windows EXE (по умолчанию надёжный ONEDIR)
- docs/WINDOWS_BUILD.md             — правила проверки собранного EXE

Как запустить на Windows:
1. Установите Python 3.10–3.13 и отметьте галочку "Add Python to PATH".
2. Распакуйте архив в отдельную папку.
3. Запустите "Установить_зависимости.bat". Скрипт проверит Python-библиотеки, FFmpeg и ffprobe.
   Если FFmpeg отсутствует, на Windows автоматически скачивается portable release-essentials build,
   проверяется его опубликованный SHA-256 и рядом с программой кладутся только ffmpeg.exe/ffprobe.exe.
4. Запустите "Запустить.bat".
5. Добавьте видео, нажмите обработку и выберите папку сохранения. Задача появится на вкладке «Задачи», куда программа переключится автоматически. Пока она выполняется, можно добавить следующие переводы — они встанут в очередь.


Сборка EXE:
- `build_exe.bat` устанавливает build-зависимости, гарантирует наличие ffmpeg+ffprobe и собирает `dist\VideoTranslatorPRO\VideoTranslatorPRO.exe`.
- Собранный artifact всегда получает собственную пару ffmpeg/ffprobe: локальную или найденную в PATH машины сборки.
- По умолчанию используется ONEDIR: он надёжнее для Whisper/torch/локальных AI-библиотек и проще для диагностики.
- `build_exe.bat --onefile` используйте только после успешной проверки ONEDIR на Windows.
- В EXE Python-движки Argos/Marian/Piper должны быть включены при сборке; модели и голоса после этого ставятся из вкладки программы.
- Если EXE установлен в защищённую от записи папку (например, Program Files), изменяемые runtime-данные автоматически сохраняются в `%LOCALAPPDATA%\VideoTranslatorPRO`: `logs`, `Логи проблем`, `translated_texts` и `tts_cache`. В portable-папке с правом записи прежнее расположение рядом с программой сохраняется. Корень можно явно задать через `VIDEO_TRANSLATOR_RUNTIME_DIR`.

Диагностика и восстановление после сетевых ошибок:
- При каждом запуске в папке "Логи проблем" создаётся отдельная папка session_<ID>.
- Начинайте разбор с "Логи проблем\latest_session.json": он указывает на последнюю
  сессию и её report.md. README_FOR_CODEX.md объясняет Codex порядок чтения.
- В каждой сессии есть: report.md (краткий вывод), summary.json (состояние пакета,
  группы проблем и кандидаты на улучшения), problems.jsonl (только warning/error),
  events.jsonl (полная хронология) и manifest.json (схема и границы проверки).
- events.jsonl хранит информационную временную шкалу, problems.jsonl — только проблемы;
  дублировать warning/error в обоих файлах больше не требуется. Общий sequence сохраняет порядок.
- Частые одинаковые retry/heartbeat/progress сохраняются выборочно: первые 3, затем
  5/10/20/50/100 и каждый 250-й. Точное число occurrences_total и последний контекст
  всегда находятся в summary.json, поэтому размер уменьшается без потери факта повторов.
- Каждая проблема содержит устойчивую сигнатуру. В issue_cards Codex получает отдельно
  подтверждённые доказательства, вероятную причину, места поиска в коде, способ исправления
  и проверку результата. Сводка также проверяет наличие stage/input_path/traceback.
- Если предыдущая сессия больше 15 минут оставалась в состоянии running, при
  следующем запуске она помечается как прерванная. Старые журналы плоского формата
  без удаления переносятся в "Логи проблем\legacy_flat_logs".
- Секреты, токены и длинные служебные URL в этих логах скрываются.
- Во время перевода создаются контрольные точки в папке
  translated_texts\Контрольные точки. После сетевого сбоя повторный запуск
  восстанавливает уже переведённые сегменты и продолжает с пропущенных.
- Перевод выполняется безопасными пачками. Если хотя бы один служебный разделитель
  изменился или исчез, вся пачка отклоняется и переводится по одному сегменту.
- Один requests.Session повторно использует TLS-соединение. При шквале ошибок
  программа делает передышку 30–60 секунд и пишет одно событие начала/окончания шторма.
- Во время долгого распознавания и работы ffmpeg программа раз в минуту пишет,
  что операция продолжается — это помогает отличить работу от зависания.

Очередь задач и продолжение после перезапуска:
- Каждое нажатие «Начать обработку» создаёт отдельную задачу со снимком файлов, папки результата и настроек.
- Вкладка «Задачи» показывает задачи в FIFO-порядке; одновременно выполняется только одна, остальные ждут.
- Очередь атомарно сохраняется в translated_texts\Контрольные точки\translation_tasks.json.
- Если программа закрылась во время перевода, running-задача при следующем запуске становится продолжимой и автоматически возвращается в выполнение по своему месту в очереди.
- Внутри активной задачи сохраняется совместимая контрольная точка latest_batch_recovery.json; старые single-batch состояния автоматически мигрируют в новую очередь.
- Уже успешные файлы не запускаются повторно. Если MP4 успел появиться непосредственно перед прерыванием, он считается готовым только после проверки ffprobe на наличие видео и аудио.
- Переведённые текстовые сегменты и TTS-кэш сохраняются отдельными checkpoints, поэтому продолжение не обязано начинать длинное видео с нуля.
- Изменённый входной файл или существующий непроверенный результат не перезаписывается: программа выбирает новое свободное имя результата.
- После завершения задачи Windows показывает системное уведомление поверх остальных окон; затем программа может перейти к следующей задаче очереди.

Восстановление озвучки:
- Папка tts_cache хранит Edge TTS/gTTS и подготовленные WAV по тексту, голосу,
  скорости и настройкам звука. При ошибке или отмене кэш переживает перезапуск
  программы и позволяет продолжить обработку.
- Уже созданные и нормализованные фразы восстанавливаются без повторной загрузки;
  при необходимости заново выполняется только подгонка к таймингу конкретного видео.
- После успешной проверки готового MP4 программа удаляет только записи кэша,
  которые использовались этим видео: для завершённой работы они больше не нужны.
- При ошибке или отмене тяжёлые подготовленные WAV удаляются сразу, а компактные
  MP3 сохраняются до 7 дней: по ним озвучку можно продолжить без повторного запроса к сети.
- После аварийного закрытия оставшиеся подготовленные WAV хранятся не более 24 часов;
  незавершённые пары и временные *.tmp — также до 24 часов.
- Если recovery-кэш превысит 2 ГБ, сначала удаляются подготовленные WAV, затем самые
  старые записи, пока размер не уменьшится примерно до 1,5 ГБ.
- Во время обработки программа периодически проверяет размер папки и перестаёт
  добавлять производные WAV при достижении 2 ГБ; компактные MP3 для восстановления
  при этом продолжают сохраняться.
  Файлы с именами, не похожими на служебный SHA-256 ключ программы, не удаляются.
- Одновременно готовятся до трёх сегментов, но в финальный таймлайн они всегда
  попадают в исходном порядке.
- При работе через VPN одновременно выполняются не более двух сетевых запросов
  Edge TTS и двух запросов gTTS. Локальная обработка по-прежнему идёт в три потока.
- Если Edge TTS нестабилен, программа НЕ показывает окно «смените VPN» и не ждёт
  действий пользователя. Маршрут выбирается автоматически: выбранный Edge-голос →
  установленные локальные Piper-голоса по очереди → gTTS.
- Если один локальный Piper-голос повреждён или не может синтезировать сегмент,
  программа пробует следующий установленный Piper-голос и только затем сетевой резерв.
- Для перевода действует такой же принцип: MarianMT → Argos (локально), затем
  selective Google Repair. У Google автоматически переключаются два сетевых endpoint,
  а при недоступности online repair уже полученный локальный перевод не теряется.
- gTTS не умеет выбирать заданный Edge-голос, поэтому тембр резервных фраз может
  отличаться; это фиксируется в логах, но отдельного подтверждения не требуется.
- Кэш подготовленных WAV разделён по фактическому источнику Edge TTS/gTTS:
  резервный женский голос больше не выдаётся из кэша за выбранный мужской.
- Сегменты, не созданные в параллельном проходе, повторяются по одному перед тем,
  как программа признает этап озвучки неудачным.

Главное изменение Pause Sync:
- Программа больше не пытается любой ценой втиснуть длинную русскую фразу в короткий английский слот.
- В интерфейсе можно выбрать предел x1.15, x1.20 или x1.25.
- Если для попадания нужно ускорение выше выбранного предела, голос НЕ ускоряется дальше и НЕ обрезается.
- Вместо этого видео вставляет стоп-кадр/паузу в момент, где фраза перестала помещаться.
- Русская фраза спокойно договаривается, затем видео продолжается дальше.
- Итоговое видео может стать немного длиннее оригинала, зато перевод остаётся полным, а голос меньше роботизируется.

Качество голоса:
- Сначала программа использует естественные паузы между английскими репликами.
- Затем пробует нативный rate Edge TTS в пределах безопасного лимита.
- Затем применяет tempo-stretch без изменения pitch: rubberband, если он есть в ffmpeg, иначе atempo.
- Общий предел ускорения голоса настраивается: x1.15 / x1.20 / x1.25.
- Фразы не обрезаются ради синхронизации.
- Русская дорожка проходит loudness-normalization и limiter.

Исправление финального MP4:
- Итоговый файл собирается напрямую через ffmpeg, а не через MoviePy write_videofile.
- Программа больше не должна оставлять *_TEMP_MPY_wvf_snd.mp4 как результат.
- В выбранной папке должен появляться нормальный файл *_RU.mp4 с видеодорожкой и русской озвучкой.
- Перед переносом в выбранную папку программа проверяет, что MP4 содержит и video, и audio stream.
- Все временные файлы создаются в системной TEMP-папке и удаляются после обработки.

Отчёт:
- Рядом с готовым MP4 создаётся файл *_segments.txt.
- В нём можно проверить весь распознанный английский текст, русский перевод и список вставленных пауз.

Рекомендации:
- Для лучшего распознавания используйте модель small или medium.
- Medium без GPU может работать очень долго.
- Если оставляете оригинальный английский звук фоном, ставьте громкость 8–15%.
- Если хотите максимально чистую русскую озвучку без английского голоса — выключите "Оставить оригинальный звук фоном".

НАДЁЖНОСТЬ V9 — ДОПОЛНИТЕЛЬНАЯ ПРОХОДКА
------------------------------------------------
- Обычный pytest изолирован от исторических repair_evidence и проверяет только актуальные tests/.
- Старые копии исходников из repair_evidence удалены; сохранены отчёты и verification evidence.
- Настройки сохраняются атомарно через временный файл + os.replace; ошибки чтения/записи больше не молчат.
- Google Repair замечает остатки исходных слов не только для English→Russian, но и для других
  поддержанных латинских языков, а также заметные остатки японского/китайского/корейского/
  арабского/греческого/иврита в русском локальном переводе.
- MarianMT скачивается сразу в managed model directory, без второй полной копии модели в общем HF cache.
- ffmpeg рядом с программой имеет приоритет над глобальным PATH, что делает EXE воспроизводимее.
- Большие portable/model downloads сохраняют частичный файл и могут продолжаться после повторного запуска.
- Установленные локальные модели и Piper-голоса хранятся постоянно в профиле пользователя (`~/.video_translator_models`), а не рядом с временной распаковкой/EXE. Обновление архива или программы не требует ставить их заново.
- При каждом запуске программа делает быструю локальную проверку уже установленных компонентов и сразу замечает смену совместимого каталога приложения. Полная SHA-256/JSON-проверка тяжёлых голосов выполняется не чаще раза в 7 дней, если всё исправно; найденное повреждение проверяется снова на следующем запуске, пока не будет устранено. Любая загрузка/обновление требует подтверждения пользователя. Проверку можно отключить во вкладке «Переводчики и голоса».
- Пока идёт обработка видео, установка/удаление/обновление моделей заблокированы; и наоборот, запуск видео блокируется на время изменения model store.

HYBRID AI V9 — ЛОКАЛЬНЫЙ ПЕРЕВОД И ГОЛОСА
-----------------------------------------
Во вкладке «Переводчики и голоса» можно установить локальные Argos/MarianMT и
русские голоса Piper. Программа умеет переводить основную массу текста локально,
а Google использовать только для точечного исправления подозрительных сегментов.
Размер каждой локальной модели/голоса показывается до загрузки. Большие модели
не скачиваются автоматически без явной установки; исключение — языковые пакеты Argos после определения языка, если Argos уже установлен
и включена соответствующая настройка. Если прямого маршрута к русскому нет, программа
может поставить source→English и English→Russian и использовать штатный pivot Argos.
Большие загрузки умеют продолжаться из .part после обрыва. Голоса и модели после установки
сохраняются в постоянном каталоге профиля пользователя и повторно не загружаются при каждом запуске.
Быстрая проверка выполняется при запуске, а глубокая проверка целостности — периодически; программа только предлагает восстановление/обновление и ничего не скачивает без подтверждения.
Если исходный язык уже совпадает с языком результата, сетевой перевод вообще пропускается. Подробности:
docs/HYBRID_AI_V9.md.
